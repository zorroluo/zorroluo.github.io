## Markdown基础练习

### 1.如何显示标题，也就是加粗放大的字体：
源码：
```
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题
```

以上代码渲染结果如下：
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题

注意：# 后面必须加空格，不加空格渲染失败。

### 2.文字样式：加粗、斜体、删除线
源码：
```
普通文字
**加粗文字**
*斜体文字*
***加粗斜体文字***
~~这行文字被划掉~~
```

以上代码渲染结果如下:

普通文字  
**加粗文字**  
*斜体文字*  
***加粗斜体文字***  
~~这行文字被划掉~~  
### 3.换行与分段

- **分段**：两行之间空一行即可
- **强制换行**：一行末尾加两个空格之后再按回车

源码：
```
第一段文字

第二段文字
```

### 4.无序列表
源码：
```
- 第一项
- 第二项
- 第三项
```

以上代码渲染结果如下：

- 第一项
- 第二项
- 第三项

注意：- 后面要有空格。

### 5.有序列表
源码：
```
1. 第一步
2. 第二步
3. 第三步
```

以上代码渲染结果如下：

1. 第一步
2. 第二步
3. 第三步  

注意：\. 号后面一定要有空格。

### 6.行内代码（适合命令、变量、文件名）
反引号 ` （键盘左上角，Esc 正下方)  
源码：
```
使用命令 `pelican content` 生成网页。
配置文件名字：`pelicanconf.py`
```

以上代码渲染结果如下:  
使用命令 `pelican content` 生成网页  
配置文件名字：`pelicanconf.py`

### 7. 代码块（多行代码，写 bash，Python 命令必备）
前后三个反引号 ```  
源码：
````
```bash
pelican content
ghp-import output -b gh-pages
git push origin gh-pages
```
````

以上代码渲染结果：
```bash
pelican content
ghp-import output -b gh-pages
git push origin gh-pages
```

注意1：想要显示代码块的源码，外层可以用前后四个反引号 ````。  
注意2：第一行 ``` 后面协商语言名称bash/python，可以开启语法高亮。

### 8. 超链接
格式：`[显示文字](网址)`  
源码：
```
[前往我的 Github](https://github.com/zorroluo)
```

以上代码渲染结果如下:  
[前往我的 Github](https://github.com/zorroluo)

### 9. 插入图片
格式：`![图片提示文字](图片路径)`  
源码：
```
![我的博客头像](images/icon_about_free.jpg)
```

以上代码渲染结果如下：
![我的博客头像](images/icon_about_free.jpg)  
注意：在pelican项目里，图片一般放在`content/images/`
### 10. 引用块（引用一句话）
源码：
```
> 这是一段引用的文字
> 可以多行引用
```

以上代码渲染结果如下：
> 这是一段引用的文字  
> 可以多行引用

### 11. 水平分割线
源码：
```
---
```

以上代码渲染结果如下：

---

### 12.转义符 \ (推荐，纯文本展示用的)
源码：
```
\# 一级标题
```

以上代码渲染结果如下：  
\# 一级标题  
原理：`\`就是Markdown的"取消魔法符号"  
需要转义的常见符号：`# * - > [] ()`都可以前面加`\`

### 13. VSCode内置的markdown解析器与 Pelican默认的markdown解析器不同
**VSCode 内置预览 ≠ Pelican 默认 Markdown 解析器，两套解析规则不一样，VSCode 宽松容错，Pelican 默认严格**，这是非常高频的坑。

1. VSCode 默认预览用 **GFM / CommonMark（GitHub 风格）**，容错很强
2. Pelican 默认用 **Python-Markdown（原始标准 Markdown）**，对块级语法规则严格得多，和 GFM 行为有明确差异
你遇到的三个现象，全部是这个解析器差异导致，下面逐个拆解、给修复方案。

**处理方案：写兼容 Python-Markdown 的规范写法（推荐，零改配置、最稳）**

适配 Pelican 原生规则，也是静态博客最佳实践：

1. **任何列表、代码块、标题、引用，前面必须留一个空行**
2. 分段用**空一行**，不要依赖单回车
3. 真的需要段落内强制换行：行尾 2 个空格 + 回车，或者直接写 HTML `<br>`
